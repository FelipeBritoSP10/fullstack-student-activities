# 🚀 Student Dev Activities

Repositório destinado ao desenvolvimento, organização, entrega e avaliação das atividades práticas de desenvolvimento web.

O objetivo é acompanhar a evolução técnica do aluno através de exercícios e pequenos projetos utilizando diferentes tecnologias e conceitos fundamentais do desenvolvimento de software.

---

## 🎯 Objetivo

Este repositório foi criado para centralizar as atividades desenvolvidas durante o processo de aprendizagem.

Aqui serão trabalhados:

- HTML
- CSS
- JavaScript
- Tailwind CSS
- Git
- GitHub
- Organização de código
- Lógica de programação
- Boas práticas de desenvolvimento

O foco não é apenas entregar uma aplicação funcionando, mas compreender o código desenvolvido e conseguir explicar as decisões tomadas durante a implementação.

---

## 🌿 Branches

Cada atividade deverá ser desenvolvida em uma branch específica.

Exemplo:

```bash
git checkout -b feat/html-atividade-01
```

Outros exemplos:

```text
feat/css-atividade-01
feat/js-atividade-01
feat/tailwind-atividade-01
```

> Não desenvolver diretamente na branch `main`.

A branch `main` deverá conter apenas atividades revisadas e aprovadas.

---

## 📝 Commits

Os commits devem ser objetivos e descrever claramente a alteração realizada.

### Exemplos

```bash
git commit -m "feat: cria estrutura da página"
```

```bash
git commit -m "style: adiciona responsividade"
```

```bash
git commit -m "feat: implementa validação do formulário"
```

```bash
git commit -m "fix: corrige comportamento do botão"
```

### Tipos de commit

| Tipo       | Utilização           |
| ---------- | --------------------- |
| `feat`     | Nova funcionalidade  |
| `fix`      | Correção de problema |
| `style`    | Alterações visuais   |
| `refactor` | Melhoria estrutural  |
| `docs`     | Documentação         |
| `test`     | Testes               |

---

## 🔀 Pull Request

Após finalizar uma atividade, deverá ser criado um Pull Request direcionado para a branch `main`.

### Exemplo

```text
feat: entrega atividade HTML 01
```

### O Pull Request deve informar:

* O que foi desenvolvido
* Quais conceitos foram utilizados
* Quais dificuldades foram encontradas
* Como os problemas foram solucionados
* O que foi aprendido
* O que ainda pode ser melhorado

## ✅ Critérios de avaliação

As atividades serão avaliadas considerando:

### 01 — Funcionamento

* A aplicação funciona conforme os requisitos?
* As funcionalidades foram implementadas corretamente?

### 02 — Fundamentos

* O aluno compreende os conceitos utilizados?
* Os fundamentos ensinados foram aplicados corretamente?

### 03 — Código

* O código está organizado?
* Os nomes são claros?
* O código é legível?
* Existe repetição desnecessária?

### 04 — Organização

* Os arquivos estão organizados?
* A estrutura do projeto faz sentido?
* As responsabilidades estão bem separadas?

### 05 — Boas práticas

* O código segue boas práticas compatíveis com o conteúdo estudado?
* Foram evitadas soluções desnecessariamente complexas?

### 06 — Responsividade

Quando aplicável:

* A interface funciona em diferentes tamanhos de tela?
* Os elementos permanecem utilizáveis em dispositivos menores?

### 07 — Git e GitHub

* Branch utilizada corretamente?
* Commits organizados?
* Pull Request criado corretamente?
* Histórico de alterações compreensível?

### 08 — Compreensão

O aluno deverá conseguir explicar:

* O funcionamento do código
* A lógica utilizada
* As decisões tomadas
* Os problemas encontrados
* As soluções implementadas
* Possíveis alternativas

## 🏗️ Organização do código

Durante as atividades, priorizar:

* Nomes descritivos
* Estrutura simples
* Responsabilidades bem definidas
* Código legível
* Arquivos organizados
* Evitar duplicação desnecessária
* Evitar complexidade sem necessidade
* Comentários apenas quando realmente necessários

---

## 🔐 Segurança

Nunca enviar para o GitHub:

* Senhas
* Tokens
* API Keys
* Credenciais
* Dados pessoais sensíveis
* Arquivos `.env`
* Informações privadas

Quando necessário, utilizar:

```text
.env
```

e adicionar o arquivo ao:

```text
.gitignore
```

---

## 🚫 O que evitar

* Desenvolver diretamente na `main`
* Commits genéricos como `update` ou `teste`
* Código copiado sem compreensão
* Arquivos desnecessários
* Código duplicado
* Bibliotecas sem necessidade
* Credenciais no repositório
* Ignorar erros do console
* Entregar sem testar
* Abrir Pull Request sem descrição
* Utilizar soluções que não consegue explicar
